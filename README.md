# RF 스위퍼

시험장 입실 전의 BLE·Wi-Fi 환경을 스냅샷으로 저장하고 입실 후·시험 중 관측과 비교하는 Android 앱입니다. 추가된 주소, 이번에 관측되지 않은 주소, 공통 주소의 신호 세기 변화를 확인합니다. 제조사·모델 후보와 관측 시각을 함께 보관합니다.

처음 사용한다면 [화면으로 보는 사용 순서](docs/QUICKSTART.ko.md)를 확인하세요.

## 사용 흐름

1. 수험생이 입실하기 전 실제 탐색을 시작하고 BLE·Wi-Fi 결과를 기다립니다. 비교 탭이 첫 화면입니다.
2. 공간 이름(예: 제1시험실)을 입력하고 `① 입실 전 저장`을 누릅니다.
3. 입실 후 같은 자리에서 `② 입실 후 저장하고 비교`를 누릅니다. 저장이 끝나면 기록 양식이 접히고 결과로 이동합니다. 다른 시점 이름이나 기준 재설정은 `다른 시점·기준 다시 설정`에서 엽니다.
4. 추가 신호를 누르면 주소, 종류, 제조사·모델 후보, 최초·마지막 관측과 수신 횟수를 확인합니다. 추가 주소는 확인 후보이며 부정행위 판정이 아닙니다.
5. 저장된 자료는 탐색을 중지하거나 앱을 다시 열어도 남습니다. 저장 목록에서 기준과 대상을 다시 선택할 수 있습니다. 같은 공간·같은 실제/연습 모드이고 대상이 기준 이후 시점이어야 비교됩니다.
6. 기기 탭에서는 이름·제조사·모델 후보·MAC 검색, 신규/최근 수신/수신 기록/BLE/Wi-Fi 필터를 사용합니다. 연습 모드에서 가상 이어폰을 추가해 전체 과정을 체험할 수 있습니다.
7. 저장 목록에서 공간·시점 이름을 검색하거나 `이 공간만`으로 자료를 좁힙니다. 목록 검색은 이미 선택한 기준·대상을 바꾸지 않습니다.

첫 저장에서 측정 공간을 확정합니다. 이후 다른 공간을 측정하려면 탐색을 중지하고 공간 이름을 바꾼 뒤 새 탐색을 시작합니다. 확정된 세션의 자료를 이름만 바꿔 다른 공간에 저장할 수 없습니다. 다른 공간의 기준 자료를 열어도 현재 공간의 신호에 신규 경보를 적용하지 않습니다. 저장 중 새 세션을 시작해도 이전 저장 결과가 새 세션의 기준 선택을 덮어쓰지 않습니다.

## 비교 결과 분석

- 비교를 저장하면 기록 양식이 접혀 결과 영역을 넓게 사용할 수 있습니다. 결과 아래의 `새 스냅샷 기록`으로 다시 엽니다.
- 기본 흐름은 입실 전 저장 → 입실 후 비교 → 추가 장비 확인입니다. 세 단계는 스크롤 영역 위에 고정하고 현재 단계와 완료 상태를 표시합니다. 비교 카드에는 유형·제조사 단서·모델 후보·관측 시간 네 가지를 우선 표시합니다.
- 검색·필터·정렬, 비교 시점, 이전 기록은 필요할 때 펼칩니다. 추가는 기준에 없던 주소, 미관측은 기준에는 있지만 이번 자료에는 없는 주소, 공통은 양쪽에 기록된 주소입니다. 한 줄 뜻은 바로 표시하고 긴 설명은 `결과 의미 보기`에서 엽니다. 장비 상세의 원본 주소·수신 세기·식별 근거·시간 해석과 시점별 기록도 각각 펼쳐봅니다.
- 비교 카드와 기기 목록·상세에 장비 유형, 관측 구간, 수신 횟수를 표시합니다. 비교 카드·상세에는 최초·마지막 시각도 표시합니다. Wi-Fi는 접속점(공유기/핫스폿), BLE는 이름에서 읽은 이어폰·헤드폰·오디오 후보 또는 유형 미확인으로 구분합니다. 제조사만으로 휴대폰·이어폰 유형을 추측하지 않습니다.
- 관측 구간은 같은 탐색에서 최초~마지막 수신까지의 범위이며 연속 송신·연결 시간이 아닙니다. 중간 공백은 알 수 없고 한 번 수신했을 때는 기간 판단 불가로 표시합니다. 미관측 그룹 카드의 상태와 시간은 기준 자료에 기록된 값임을 명시합니다.
- 추가·미관측·공통 그룹마다 이름·제조사·모델·MAC을 검색하고 BLE/Wi-Fi 및 오디오 후보 필터를 함께 적용합니다. 한글 브랜드 별칭, 여러 검색어, 구분자를 생략한 MAC도 검색합니다. 필터 후 표시 건수와 원래 그룹 건수는 구분합니다.
- 강한 신호순, 최근 관측순, 수신 횟수순, 이름순으로 정렬합니다. 공통 그룹은 RSSI 변화의 절댓값이 큰 순서도 제공합니다. 정렬은 관측 자료를 탐색하기 위한 것이며 부정행위 위험 점수가 아닙니다.
- 신호 상세에는 같은 공간·같은 모드에서 해당 비교 시점까지 저장된 관측 이력을 시간순으로 표시합니다. 주소가 없는 스냅샷도 `미관측`으로 남기며 다른 공간·연습 자료·미래 자료를 섞지 않습니다. 여러 스냅샷의 세션 누적 수신 횟수를 더하지 않습니다.

레이더와 근접 진동에는 최근 수신한 신호만 반영합니다. 방향 미확정 기기는 개수와 기기 목록으로 확인합니다. BLE는 5초 이내 최근 수신, 15초 이내 수신 대기, 이후 수신 기록으로 표시합니다. Wi-Fi는 갱신 주기를 고려해 각각 45초·90초를 사용합니다. 수신이 끊겼다는 표시는 기기가 꺼졌거나 공간을 떠났다는 확정 판단이 아닙니다.

앱을 벗어나거나 화면을 끄면 탐색이 중지됩니다. 새 탐색 세션은 실시간 이력을 초기화하지만 선택한 저장 기준은 유지합니다. 모드를 바꾸면 기준 선택이 해제되며 저장된 스냅샷은 삭제되지 않습니다. 앱 재실행 후에는 저장 목록에서 기준을 다시 선택합니다.

## 빠른 포착과 스냅샷의 범위

- BLE는 LOW_LATENCY·ALL_MATCHES·보고 지연 0으로 연속 수신을 요청합니다. 빠르게 스캔을 중지·재시작하는 폴링을 하지 않습니다. OS·하드웨어·상대 기기의 광고 주기가 실제 수신 빈도를 결정합니다.
- 수신 콜백에서 관측을 즉시 추적기에 기록하며 화면 집계는 100ms 주기입니다. 화면 100ms는 무선 패킷을 100ms마다 반드시 수신한다는 의미가 아닙니다. 배치 전달도 처리하고 실제 패킷 타임스탬프를 보존합니다.
- 한 번 포착된 주소도 세션 동안 남기고 수신 횟수·최고 RSSI·마지막 수신 경과를 표시합니다. 기준 이후 새 주소가 들어오면 모든 탭에서 배너로 알립니다. 오래된 신호로 근접 진동이나 레이더 위치를 유지하지 않습니다.
- 기준 스냅샷은 최근 관측 범위(BLE 15초·Wi-Fi 90초)의 주소를 저장합니다. 비교 스냅샷은 최근 관측에 더해 기준 이후 포착된 신규 주소의 이력을 포함합니다. 잠깐 등장했다가 사라져도 추가 기록을 남기며 저장 당시 수신 상태와 시각으로 현재 수신과 구분합니다.
- Wi-Fi 능동 요청은 기본 30초입니다. Android의 전면 앱 제한(일반적으로 2분당 4회)을 따르고 다른 앱·플랫폼의 완료 브로드캐스트도 수신합니다. 연속 BLE와 같은 초고속 수신을 보장하지 않습니다.
- Wi-Fi는 새 세션 시작 이후 실제로 관측된 결과만 받습니다. 이전 공간에서 얻은 시스템 캐시와 중지한 수신기의 지연 콜백을 새 공간에 배정하지 않습니다. 새 탐색 직후에는 새로운 결과를 기다려야 합니다.
- 같은 MAC이라도 BLE와 Wi-Fi를 별도 기록으로 추적합니다. 주소의 대소문자는 같은 것으로 처리하며, 지연 도착한 패킷이 최신 RSSI·마지막 관측 시각을 과거로 되돌리지 않도록 합니다.
- 자료는 앱 내부의 버전 있는 JSON 파일로 보관합니다. 임시 파일을 동기화한 뒤 교체하여 저장하며, 파일을 읽을 수 없으면 기존 자료를 빈 목록으로 덮어쓰지 않습니다. 저장된 시점은 이후 수신으로 바뀌지 않습니다.

## 제조사와 모델 식별

- IEEE MA-L 등록부 40,500개 접두어로 전역 유니캐스트 MAC의 등록 조직을 조회합니다.
- Bluetooth SIG 회사 식별자 4,075개로 BLE 제조사별 광고 데이터의 회사 코드를 해석합니다.
- AirPods/에어팟, Galaxy Buds/갤럭시 버즈, Sony WF/WH/WI, Bose QuietComfort/SoundSport, Pixel Buds, Jabra Elite, Beats, Nothing Ear, soundcore Liberty/Space A40, Sennheiser MOMENTUM True Wireless 계열의 광고 이름 규칙으로 모델 후보를 읽습니다. 이름에 없는 세대·모델은 추측하지 않습니다. 괄호 안 세대 표기와 전각 문자도 처리합니다.
- 이어폰·헤드폰·오디오 후보를 구분합니다. 광고 회사만 Apple이라고 해서 이어폰으로 분류하지 않으며 Wi-Fi SSID를 오디오 기기로 분류하지 않습니다. `Elite router` 같은 일반 이름은 제품 모델로 해석하지 않습니다.
- 모델 카드에 이름 기반 후보임을 표시합니다. 이름과 해석 가능한 광고 회사의 브랜드 근거가 다르면 함께 확인하도록 표시합니다. 광고 회사 코드 자체를 제품 인증 결과로 취급하지 않습니다.
- 이름·제조사 검색은 모든 광고 회사, MAC 등록사, 이름 기반 브랜드·모델을 확인합니다. 알려지지 않은 회사 코드가 알려진 회사 이름을 가리지 않도록 표시 순서를 정합니다.
- 저장된 스냅샷의 원본 이름·모델 필드는 변경하지 않습니다. 현재 이름 규칙으로 더 상세한 후보를 읽을 수 있으면 상세 화면에서 저장 당시 후보와 현재 해석을 구분합니다.
- 로컬 관리 MAC은 등록 조직 조회에서 제외합니다. BLE 임의 주소가 전역 주소처럼 보일 수도 있으므로 BLE MAC 등록사는 확정 제조사가 아닙니다.
- 광고 이름과 회사 ID는 기기가 보낸 정보이며 인증된 제품 정보가 아닙니다. Wi-Fi SSID를 이어폰 모델명으로 해석하지 않습니다.
- 등록부는 앱에 포함되어 오프라인 조회합니다. MAC이나 스캔 결과를 외부 조회 서버로 전송하지 않습니다. 원본과 갱신일은 `app/src/main/assets/REGISTRY-SOURCES.txt`에 기록했습니다. MA-M/MA-S와 광고 페이로드의 비공개 모델 코드는 현재 해석하지 않습니다.

## 권한과 관측 범위

실제 탐색에는 주변 Bluetooth 기기 및 정확한 위치 권한이 필요합니다. Android 13 이상도 WifiManager 스캔 결과에는 정확한 위치 권한과 위치 서비스가 필요합니다. 신체 활동 권한은 보행 기반 방향 추정에 사용하며 거부해도 신호 탐색은 가능합니다. 걸음 센서가 없는 기기에서는 실제 보행을 반영한 방향 추정을 제공하지 못할 수 있습니다.

Wi-Fi 결과는 완료 브로드캐스트 이후 반영하고, 관측 시각은 실제 스캔 타임스탬프를 사용합니다. 시스템 제한으로 요청이 지연될 수 있습니다. 채널 차트는 AP 수이며 실제 트래픽 혼잡도나 간섭 측정값이 아닙니다. BLE 광고·Wi-Fi AP를 관측하므로 모든 휴대폰이나 연결 중인 이어폰의 존재를 보장하지 않습니다. RSSI 거리·방향은 추정값이며 부정행위나 특정 기기 소유자의 증거가 아닙니다.

## 빌드와 검증

JDK 17 이상, Android SDK 35가 필요합니다. `local.properties`의 SDK 경로를 환경에 맞게 설정하세요.

```powershell
./gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

단위 테스트는 신호 정렬, 신규 우선순위, 기준점 재설정, 관측 만료와 재등장, 채널/대역 해석, 임의 MAC 처리, 모델 추출 범위, 제조사 코드 유지와 공식 등록부 형식을 검사합니다.

현재 65개 테스트가 통과했습니다. Robolectric의 Android 런타임과 네이티브 그래픽 및 JVM 단위 테스트로 다음을 검증합니다.

- 탐색 시작 → 기준점 저장 → 가상 이어폰 추가 → 신규 1대 → Apple 광고 회사·AirPods Pro 모델 후보 상세 → 중지 → 새 세션에 선택된 기준 유지.
- 입실 전 5개 주소 저장 → 이어폰 추가 → 입실 후 6개 저장 → 추가 1·공통 5·미관측 0 → 저장 신호 상세 열기 → 탐색을 중지한 뒤 같은 비교 결과 확인.
- 비교 결과 검색으로 0개를 표시해도 원래 추가 1개 집계가 유지되는지, 검색 해제·오디오 필터·수신 횟수순 정렬·관측 타임라인 열기가 동작하는지 확인.
- 한글·영문 모델과 세대 표기, 일반 단어 오인식 방지, 영문·한글 별칭과 구분자 없는 MAC 검색, 이름·회사 코드 근거 차이, 시점별 미관측 항목과 미래·다른 공간 자료 제외를 확인.
- 저장소를 새로 생성한 뒤 한글·null 필드를 포함한 여러 시점 복원, 지원하지 않는 파일 버전 거부, 다른 공간/실제·연습 모드/역순 시점 비교 거부.

화면 캡처는 `app/build/outputs/ui-captures/`에 생성됩니다. 레이더·기기·이어폰 상세·작은 화면·가로 화면 외에 `snapshot-comparison.png`, `snapshot-audio-analysis.png`, `snapshot-signal-detail.png`, `snapshot-signal-timeline.png`, `snapshot-library.png`로 시점 비교·식별 근거·저장 목록 UI를 검토합니다. 작은 화면에서는 헤더·권한 안내를 간결하게 표시하고, 가로 화면에서는 레이더 폭을 제한합니다.

실물 이어폰 광고 수신과 실제 RF 환경에서의 거리·방위 정확도는 아직 현장 검증하지 못했습니다. JVM UI 검증은 물리 Bluetooth/Wi-Fi 하드웨어 수신, 시스템 권한 대화상자, 실제 회전 센서 동작까지 보장하지 않습니다. 로컬 AVD는 ADB 기본 포트의 Windows 소켓 오류 10013과 부팅 문제로 사용할 수 없었습니다.
